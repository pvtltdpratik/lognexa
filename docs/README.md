# Lognexa — AI-Driven Access Log Auditing & Anomaly Detection

Lognexa is a final-year B.E./B.Tech CSE prototype that audits user access logs.
It combines **explainable rule-based detection** with an **Isolation Forest**
model, assigns every event a 0–100 **risk score** with a severity level
(Low / Medium / High / Critical), and raises **explainable alerts** that analysts
can acknowledge and resolve from a web dashboard.

> **Student prototype.** All data is 100% synthetic and generated by the project.
> Lognexa is not production security software, and the detection metrics below
> are only measured against labels the generator injected itself.

## Features (implemented)

| Area | What exists |
|---|---|
| Synthetic data | Reproducible generator: 60 users, 14 days, 2,200 events, 4 injected anomaly types, deliberate benign noise |
| Storage | `users`, `access_logs`, `risk_scores`, `alerts`, `analysis_runs` tables (PostgreSQL target, SQLite fallback/tests) |
| Detection | 10 behavioural features, 11 explainable rules, Isolation Forest (scikit-learn) |
| Scoring | Documented weighted formula + agreement bonus, 4 severity bands, per-event explanation text |
| API | FastAPI: `/health`, `/logs`, `/alerts`, `/risk-scores`, `/analyze`, `/analytics/overview`, `/users`, `/dataset/generate` |
| Dashboard | Next.js + shadcn/ui: overview charts, searchable/filterable logs, alert triage, risk methodology, analysis & evaluation |
| Validation | Pydantic on every endpoint (query, path, body), Zod + react-hook-form on the client, consistent JSON error envelope |
| Tests | 48 pytest tests (generator, features, rules, scoring, API, empty DB) |

## Quick start (Windows, PowerShell)

```bash
cd server
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env        # then edit LOGNEXA_DATABASE_URL
.venv\Scripts\python -m scripts.seed
.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
```

```bash
cd client
copy .env.example .env.local
npm install
npm run dev
```

Open <http://localhost:3000> (dashboard) and <http://localhost:8000/docs> (interactive API docs).

Full instructions, including PostgreSQL setup, are in
[setup-and-deployment.md](setup-and-deployment.md).
